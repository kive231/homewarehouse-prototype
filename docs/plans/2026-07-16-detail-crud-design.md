# 家庭仓库详情页与 CRUD 原型设计规格

日期：2026-07-16
状态：已确认，按顺序执行

## 1. 目标

在现有 6 个一级移动端页面基础上，补齐详情查看、新增、编辑、删除/归档、库存变动、层级选择、扫码承接和设置详情，使主要业务形成可验证闭环。

## 2. 已确认的设计方案

采用混合导航：

- 详情页使用独立全屏页面，顶部返回，不显示底部一级导航。
- 新增、编辑使用独立全屏表单，避免信息拥挤。
- 消耗、补货使用底部操作层，维持高频操作效率。
- 移动位置使用独立层级选择页，因为需要柜子 → 层 → 盒子的递进选择。
- 删除与归档使用确认操作层；存在子节点或库存时必须说明影响并阻止错误删除。

未采用的方案：

1. 全部操作独立页面：路径清楚，但页面数量和返回成本过高。
2. 全部操作使用底部操作层：操作快，但复杂表单和层级选择空间不足。
3. 混合导航：兼顾认知清晰、高频效率和移动端单手操作，作为本次方案。

## 3. 全局视觉与交互约束

- 设备画布统一为 320 × 682，仅做手机端。
- 风格保持 Anchored Ribbon Grid、Lavender Cream、Basic Roundness、Gentle Lift。
- 标题使用 Funnel Sans，正文使用 Inter，说明与导航标签使用 Geist。
- 主色沿用薰衣草紫 `#A881C2`；背景 `#FCFAF7`；浅紫 `#F3EAF7`。
- 页面左右安全边距 18px，基础间距使用 8pt 网格。
- 图标只使用 Lucide/Feather，不使用字符、Emoji 或无法识别的占位图标。
- 常规图标 18px，扫码图标 24px，触摸区域不小于 44px。
- 详情与 CRUD 页面不复制一级底部导航；统一使用返回按钮和清晰标题。
- 删除操作使用低饱和危险色，默认不作为首要按钮。
- 所有页面同时设计默认态、空态、校验态和危险确认态。

## 4. 页面分组与顺序

### 阶段 A：物品闭环

1. 物品详情：名称、分类、位置、库存、临期、二维码状态、最近流水。
2. 新增物品：名称、分类、位置、数量、单位、低库存阈值、保质期、二维码绑定。
3. 编辑物品：复用新增表单，预填数据，增加归档和删除入口。
4. 消耗操作层：当前库存、消耗数量、用途备注、消耗后库存预览。
5. 补货操作层：补货数量、批次、保质期、补货后库存预览。
6. 移动位置：逐层选择柜子、层、盒子，展示原位置与目标位置。
7. 删除/归档确认：说明统计与历史记录影响，要求二次确认。

### 阶段 B：空间与分类闭环

1. 空间下钻态：柜子 → 层 → 盒子，复用现有列表骨架与面包屑。
2. 盒子详情：节点信息、二维码、容量摘要、盒内物品列表。
3. 新增/编辑空间节点：名称、节点类型、归属位置、编号、备注。
4. 分类下钻态：大类 → 子类 → 细类，复用现有列表骨架。
5. 细类详情：分类信息、物品数量、该类物品列表。
6. 新增/编辑分类：名称、父级、图标、颜色、备注。
7. 删除阻断态：存在子节点或关联物品时禁止删除，并给出迁移入口。

### 阶段 C：扫码、流水与设置

1. 扫码识别中、识别成功、无法识别三个状态。
2. 物品码成功后进入物品详情；位置码成功后进入盒子详情。
3. 库存流水详情：变动前、变动量、变动后、时间、来源、备注。
4. 家庭与成员：成员列表、邀请、角色说明。
5. 提醒设置：临期提醒、低库存提醒、默认提前天数。
6. 数据与导出：导出、备份、恢复说明。
7. 关于与帮助：版本、使用帮助、反馈入口。

## 5. 核心跳转关系

```text
物品列表 → 物品详情
物品详情 → 编辑物品 / 消耗 / 补货 / 移动位置 / 归档
新增物品 → 保存 → 新物品详情
消耗或补货 → 确认 → 物品详情（库存与最近流水刷新）
移动位置 → 选择目标末级节点 → 确认 → 物品详情（位置与流水刷新）

空间列表 → 柜子 → 层 → 盒子详情 → 物品详情
分类列表 → 大类 → 子类 → 细类详情 → 物品详情

扫码 → 物品码 → 物品详情
扫码 → 位置码 → 盒子详情
库存流水 → 流水详情 → 关联物品详情
```

## 6. 数据与状态规则

- 物品必须绑定一个末级分类和一个末级位置。
- 消耗数量必须大于 0 且不超过当前库存。
- 补货数量必须大于 0；批次与保质期允许为空，但页面明确提示。
- 移动位置只允许选择盒子级节点，不能选择柜子或层。
- 所有消耗、补货和移动操作生成库存流水。
- 删除物品不直接抹除流水；优先归档，彻底删除需要危险确认。
- 空间/分类节点存在子节点或关联物品时禁止直接删除。
- 扫码结果必须根据 `target_type` 明确路由到物品或位置详情。

## 7. 异常与空状态

- 物品无流水：显示空态和“完成一次库存操作后会显示记录”。
- 库存不足：禁用确认按钮并显示最大可消耗数量。
- 无可选位置：引导先创建空间节点。
- 无可选分类：引导先创建三级分类。
- 扫码失败：提供重新扫描和手动输入编号。
- 删除受阻：列出子节点数或关联物品数，并提供迁移入口。

## 8. 验收标准

- 所有页面保持 320 × 682、相同标题体系、颜色、圆角、阴影和图标规范。
- 任何一级页入口都能明确找到返回路径，详情页不出现错误底部导航。
- 物品新增、查看、编辑、归档及三类库存变动形成完整闭环。
- 空间与分类均能逐层进入，并具备新增、修改、删除阻断与末层物品入口。
- 扫码结果能分别承接到物品详情和盒子详情。
- 所有页面不展示批注入口，批注不属于 App 业务界面。
- Pencil 全局不明图标扫描结果为 0，布局校验无非预期裁切、溢出或重叠。

## 9. 不在本轮范围

- Flutter 生产代码、后端 API、数据库与真实二维码扫描。
- 企业采购、供应商、审批、财务、多仓和复杂权限。
- 平板、桌面和响应式网页适配。
- 批量物品操作、首页自定义组件和无限层级树。
